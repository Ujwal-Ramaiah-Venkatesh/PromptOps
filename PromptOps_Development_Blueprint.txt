Executive Summary
PromptOps is an Agentic DevOps Utility that allows Project Managers and startup founders to deploy, manage, and heal cloud infrastructure using plain English commands. It replaces the routine work of DevOps Engineers, Cloud Engineers, and Site Reliability Engineers using a Triple-Agent Architecture — the Architect Agent, SRE Agent, and Security Agent — running on AWS, Azure, and GCP.

This document is the single source of truth for the entire engineering team. Every phase is broken into weeks and days, with explicit task lists, assigned owners, AI tools to use, deliverables, and risk mitigations. Nothing in this document is aspirational — every item is actionable and must be completed before the next phase begins.

1. System Architecture Overview
Before building anything, every team member must understand how the three agents relate to each other and to the outside world. This is the architectural contract that all code must conform to.

1.1 Triple-Agent Architecture

Architect Agent: Architect Agent
Receives structured JSON task lists from the NLP Parser.
Generates Terraform or Pulumi Infrastructure-as-Code (IaC).
Executes all code through a Shadow Validation sandbox before applying to live cloud.
Responsible for: deployments, scaling configs, network topology, IAM policies, cost optimisation.

SRE Agent: SRE Agent
Reads Prometheus and CloudWatch metrics every 60 seconds.
Uses Causal AI to find root cause, not just symptoms.
Generates 3-sentence plain-English RCA for the PM dashboard.
Auto-remediates low-risk events (disk full, pod crash, log rotation) without waking anyone.
Escalates with full context when human judgment is required.

Security Agent: Security Agent (OPA Guardrail)
Non-LLM layer — this is pure deterministic code, not AI.
Intercepts every proposed action from the Architect and SRE agents.
Checks action against Open Policy Agent (OPA) rules before execution.
Blocks and escalates: delete of production-tagged resource, IAM policy with *:* permissions, port 0.0.0.0/0 open.

1.2 Data Flow (End-to-End)

PM types a plain-English command into the PromptOps UI.
NLP Parser (Claude Sonnet 4 + LangGraph) converts it to structured JSON intent.
JSON routed to the relevant agent (Architect for infra, SRE for monitoring).
Agent generates a proposed action (IaC code, remediation script, scaling event).
Security Agent (OPA) intercepts and checks the proposed action against policy rules.
If blocked: PM receives an approval card with full context. No action taken until PM approves.
If approved: Shadow Validation runs the action in a sandbox environment first.
If sandbox passes: Action applied to live cloud with atomic rollback armed.
If sandbox fails: Agent revises and retries. PM notified if 3 retries fail.
Result displayed on PM Dashboard with plain-English summary.
All actions logged immutably to audit trail (S3 + DynamoDB).

1.3 Non-Negotiable Engineering Constraints

Every destructive action (DELETE, TERMINATE, DETACH) requires explicit PM approval with resource name typed back.
No action is ever applied to prod without passing the shadow validation sandbox first.
Terraform state files are version-snapshotted before every apply. Corruption triggers auto-restore, never re-apply.
Auto-remediation circuit breaker: if same service is restarted more than 3 times in 10 minutes, all automation halts.
All external text (logs, ticket descriptions) is sanitised before being fed to any LLM — prompt injection defence.
Ambiguity scoring: if LLM confidence is below 85%, action is blocked and PM is asked to clarify.
Every action carries an immutable timestamp, PM approval record, and agent decision log.

Phase 5 Risks & Mitigations
MODEL TRAINING ON WRONG DATASET [Extreme]: Explicit data_source parameter required. Data validator checks schema. PM approval for production data.
DEPLOYED MODEL CATASTROPHIC ACCURACY DROP [Extreme]: Shadow deployment mandatory 24hr. Canary rollout 48hr. Auto-rollback if drops >10%.
MODEL DRIFT UNDETECTED [High]: Dual drift detection: prediction + concept. Alerts if degrades 3 consecutive days.
HYPERPARAMETER TUNING EXHAUSTS BUDGET [High]: Cost ceiling enforced before tuning. Max jobs/cost in OPA policy.
BIASED MODEL DEPLOYED [Extreme]: Bias detection pre-approval. Models with >15% disparity flagged for manual review.
MODEL REGISTRY VERSIONING CONFLICT [Medium]: Immutable versioning with unique IDs. Optimistic locking on concurrent deployments.
TRAINING DATA CONTAINS PII [Extreme]: Data validator scans for PII patterns. Flagged datasets require legal approval.
AUTOML SELECTS WRONG ALGORITHM [Medium]: MLOps Agent reviews AutoML results. Claude validates algorithm choice. PM receives explanation.

MLOps Agent Architecture
The MLOps Agent integrates with the existing Triple-Agent Architecture (Architect, SRE, Security) to form a Quadruple-Agent system responsible for the complete machine learning lifecycle: model training, deployment with shadow testing, monitoring and drift detection, hyperparameter tuning, and ML governance.
Agent Interaction Flow
Example: PM command "Deploy fraud detection model v2.3 to production"
1. NLP Parser converts to JSON
2. Security Agent validates approval, bias tests, audit trail
3. MLOps Agent validates model performance, generates deployment config
4. Architect Agent provisions SageMaker endpoint, auto-scaling, API Gateway
5. MLOps Agent initiates 24-hour shadow deployment
6. SRE Agent monitors endpoint latency, error rate, prediction quality
7. MLOps Agent starts canary rollout: 5% → 25% → 50% → 100% over 48 hours
8. SRE Agent monitors for accuracy drops or latency spikes
9. MLOps Agent completes deployment, logs to audit trail, updates PM Dashboard
